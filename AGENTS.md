# Repository guidance

- Планы, findings и итоговые отчёты — на русском.
- `gateway` и `ledger` — отдельные Go-модули; корневой `go.work` объединяет их. Из корня запускайте `go test ./ledger/... ./gateway/...`, а не `go test ./...`.
- Для общего покрытия используйте `-coverpkg=./ledger/...,./gateway/... -coverprofile=cover.out`: тесты публичного Ledger и HTTP проходят через несколько пакетов.
- `ledger.New()` создаёт независимые in-memory репозитории. В тестах создавайте новый Ledger для каждого сценария; глобального хранилища и необходимости в Reset нет.
- HTTP-роутер находится в `gateway/internal/handler`; интеграционные тесты используют `handler.NewRouter(ledger.New())` без сетевого сервера.
- Бюджет относится к календарному месяцу UTC. HTTP создаёт бюджет текущего месяца; даты транзакций в тестах выводите из периода ответа, формат API — RFC 3339.
- Рабочие точки входа используют `ledger.Open(ctx) (Service, closeFn, error)` (PostgreSQL + Redis); `ledger.New()` предназначен для тестов без инфраструктуры. Gateway встраивает Ledger, отдельного RPC нет.
- Миграции Goose находятся в `ledger/migrations`: каждый SQL-файл содержит Up/Down. Уникальность бюджета — `(category, month)`, проверка лимита и INSERT расхода выполняются в SQL-транзакции под блокировкой бюджета.
- `LEDGER_INTEGRATION=1` включает тест с записью через Ledger в отдельную мигрированную БД; тестовые записи остаются. Не направлять на рабочую БД. Compose использует localhost:55432/56379.
- Отчёт использует UTC-даты `[from,to)` и кеш Redis на 30 секунд без инвалидирования; PostgreSQL DATE не сохраняет время суток расхода.
- Контракты хранения и `UnitOfWork` находятся в `ledger/internal/domain`; сервис не импортирует реализации репозиториев. Публичный `ledger.Service` — alias интерфейса из `internal/service`, доступный Gateway.
- Проверку лимита держите в сервисе внутри `UnitOfWork`: используйте переданные callback-репозитории. PostgreSQL блокирует месячный бюджет через `FOR UPDATE`; сумму возвращает в целых копейках. Нельзя разделять проверку и INSERT на независимые операции.
- Все методы `ledger.Service` принимают `context.Context` первым аргументом; Gateway передаёт `r.Context()`. Не заменяйте контекст запроса на `context.Background()` внутри сервиса/репозиториев.
- Таймаут Gateway — `HTTP_REQUEST_TIMEOUT` (по умолчанию `2s`); отмена и дедлайн дают `504` с `{"error":"request timeout"}`. Middleware буферизует ответы через `http.TimeoutHandler`, адаптируя его стандартный ответ.
- При промахе кеша отчёт делает `Categories` и параллельные `SumByCategory`, по горутине на категорию. Срез результатов читается после `WaitGroup.Wait`; при ошибке отменяются остальные вычисления. Heartbeat 400 мс должен завершиться до возврата расчёта. Схема БД не меняется.
